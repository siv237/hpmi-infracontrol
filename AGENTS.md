# AGENTS.md — схема LLM Wiki для проекта iRMC Viewer

Этот проект ведётся по канонам **LLM Wiki**: знания компилируются в
персистентный вики-слой, который LLM поддерживает сам. Схема ниже описывает
структуру, конвенции и рабочие процессы. Правила обязательны для всех сессий.

## Три слоя

### 1. Сырьё (`raw/`) — неизменяемо
- Исходные документы. Единственный источник правды. **LLM читает, но не
  редактирует.**
- `raw/avr_irmc_s2.jar` — бейн-код GPL-вьювера Fujitsu iRMC (Avocent/Mahogany).
  Это источник протокола. Разбирать через `file`/`unzip -l`, классы — CFR
  (`java -jar cfr-0.152.jar <класс> --outputdir ...`).

### 2. Wiki (`wiki/`) — собственность LLM
- Направленные markdown-страницы. LLM создаёт, обновляет, поддерживает и
  скрещивает ссылки. Человек читает.
- `wiki/index.md` — каталог всех страниц (ссылка + 1 строка описания + мета).
- `wiki/log.md` — хронология, append-only. Формат записей:
  `## [YYYY-MM-DD] ingest | <заголовок>` — чтобы парсилось unix-инструментами.
- `wiki/knowledge/*.md` — доменные страницы (протокол, архитектура, статус).

### 3. Схема (`AGENTS.md`)
- Этот файл. Содержит конвенции и рабочие процессы. Развивается совместно.

## Конвенции страниц

- Каждая страница = **одна сущность/тема/концепция**. Кратко, с конкретикой,
  без воды. Числовые факты (ID команд, смещения, маски) обязаны быть точными.
- Внутренние ссылки — относительные от `wiki/`, например `index.md`,
  `knowledge/irmc-protocol.md`.
- Верх страницы — H1 + 1-2 строки-резюме. Ниже — разделы по смыслу.
- Противоречия между страницами помечать явно (`> ⚠ противоречие: ...`).
- `log.md` — только факты об операциях (ingest/query/lint), без дублирования
  содержания страниц.

## Рабочие процессы

### Ingest
Когда добавляешь новый источник (или разбираешь новый класс/фрагмент):
1. Прочитай источник, кратко обсуди с человеком основные выводы.
2. Создай/обнови страницы знаний (может затрагивать 3-8 страниц сразу).
3. Обнови `index.md`.
4. Добавь запись в `log.md`.

### Query
Вопрос → прочитай `index.md`, найди страницы, синтезируй ответ с ссылками.
Хорошие ответы (сравнения, анализ, открытия) — **записывай обратно в wiki**
новыми страницами, чтобы знания накапливались.

### Lint
Периодически проверяй: противоречия, устаревшие утверждения, страницы-сироты,
упомянутые концепции без собственной страницы, недостающие ссылки, пробелы
данных (заполнить веб-поиском). Предлагай новые вопросы/источники.

## Язык
Общение с человеком, комментарии в коде и страницы wiki — на русском.
Идентификаторы/строки протокола — как в оригинале (англ., точные).

## Git — запрет коммитов
**Коммитить в git ТОЛЬКО по явному указанию человека.** Ни при каких других
условиях: ни после завершения задачи, ни «чтобы сохраниться». Пока человек
не скажет «закоммить» — только рабочая копия. Нарушение недопустимо.

## Запуск процессов — только по прямому приказу владельца
**НЕ запускать самому НИЧЕГО** (сервер, фоновый процесс, скрипт, контрольный
запуск) — если владелец прямо не сказал «запусти»/«проверь на живой системе».
Даже для «самопроверки»: запуск может повлиять на живой прод (занять порт,
процесс). Все проверки — в рабочей копии и только по приказу. Нарушение
недопустимо. Также: любые новые решения (коммиты/пуши/запуски/установки
пакетов) — только по явному приказу.

## Запуск сервера — только через ./start.sh
Пока оформляется служба, сервер запускается **только** командой `./start.sh`
(порт 1845, лог — `logs/server.log`; скрипт сам грузит `.env`, ставит
`node_modules` при первом запуске и убивает старую копию на порту). Обходных
запусков (`node server/index.js` напрямую и т.п.) — нет: лишь то, что делает
`./start.sh`.
