# Манифест модульной архитектуры: как добавить платформу

**Статус:** черновик (обсуждается). Цель — открытый проект, где любой человек
или ИИ может добавить поддержку новой серверной платформы, не трогая ядро.

## Идея

Проект не «поддерживает серверы» — он **объявляет контракты** и **сканирует
папки модулей**. Платформа = одна папка. Хочешь поддержку новой железки —
кладёшь папку-модуль; ядро само её найдёт и применит.

## Принципы (согласованы)

1. **Папка = платформа.** Всё платформенное — в `server/platforms/<id>/`:
   описание, пробы, вход, консоль (видео/HID), виртуальные носители,
   декодеры, quirks, README, тесты. Ядро не содержит ни строки про
   конкретную платформу.
2. **Ядро только объявляет методы (контракты) и сканирует папки.** Добавление
   платформы не требует правок ядра и его «адаптации».
3. **Модуль сам себя описывает:** какие модели/прошивки поддерживает, какие
   порты и способы доступа, какие методы проб, что умеет отдавать.
4. **Пробы и доступ — в папке модуля.** Явно перечислены порты и способы
   доступа. Креды (логин/пароль) — универсальная концепция **ядра** (хранение,
   шифрование, UI); а КАК их вводить (digest/форма/Basic/… ) — платформенный
   код модуля.
5. **IPMI — платформо-зависимый.** Точное перечисление, что конкретная
   платформа реально умеет отдавать (сенсоры/SEL/chassis/FRU/lan print и т.п.);
   транспорт-примитивы можно переиспользовать из ядра.
6. **Один файл-список поддержки.** Что именно поддержано, решает **один файл**
   модуля с конкретным перечислением `модель + версия прошивки`. Хочешь
   попробовать свою — добавь строку и смотри результат (статус verified /
   experimental).
7. **Ошибка модуля не роняет ядро.** Не загрузился / упал probe / упал метод —
   лог + переход к следующему модулю. Система деградирует с явным диагнозом.
8. **Формат максимально простой.** Модуль не обязан поддерживать все
   технологии — объявляет, что умеет, остальное ядро отключает.
9. **Изоляция/доверие (на усмотрение ядра):** модули — локальный доверенный
   код (без песочницы), загружаются динамически; реестр проверяет наличие
   обязательных методов и версию SDK. Модуль работает только через `sdk`,
   не лезет во внутренности ядра.

## Структура

```
server/
  platforms/
    <platform-id>/
      manifest.js     # ЕДИНЫЙ декларативный файл (см. ниже)
      index.js        # реализация контрактов (код)
      probe.js        # (опц.) методы проб, названы в manifest.probes
      README.md       # как есть, что проверено, грабли
      test.js         # (опц.) самотесты модуля (подхватывает npm test)
  sdk/                # ядро: контракты + реестр + загрузчик
    contracts.js      # интерфейсы (ConsoleClient, MediaRedirector, ...)
    registry.js       # скан platforms/, чтение manifest, сортировка, пробы
open/                 # ...
```

## Декларативный файл модуля (`manifest.js`) — пример

```js
export default {
  id: 'fujitsu-irmc-s4',
  title: 'Fujitsu iRMC S4 (AMI/SOC)',
  vendor: 'Fujitsu',
  sdk: 1,                       // требуемая версия контрактов ядра
  priority: 95,                 // порядок проб (убыв.)

  // ЕДИНЫЙ СПИСОК ПОДДЕРЖКИ: модель + прошивка (+ статус проверки)
  supported: [
    { model: 'iRMC S4', firmware: '7.69F', status: 'verified' },
    { model: 'iRMC S4', firmware: '7.*',   status: 'experimental' },
  ],

  // ДОСТУП: порты и способы (явно)
  access: {
    web:   { ports: [80, 443], secure: [false, true] },
    ipmi:  { port: 623 },
    kvm:   { transport: 'http-connect-tunnel', target: 443 },
    media: { transport: 'http-connect-tunnel', service: 'CDMEDIA' },
    login: 'digest-post-form',  // имя схемы входа, реализуемой модулем
  },

  // ЧТО УМЕЕТ отдавать (точно, не «вообще»)
  capabilities: {
    kvm: true,
    virtualMedia: ['cd', 'dvd'],
    ipmi: { sensors: true, sel: true, chassis: true, fru: 'basic', lanPrint: true },
    inventory: { web: false, ipmi: true },
  },

  // МЕТОДЫ ПРОБ (реализуются в этой папке; ядро лишь вызывает по имени)
  probes: ['web-title', 'jnlp-args'],
};
```

## Контракты (что реализует `index.js` модуля)

```js
export default {
  // 1) Подходит ли модуль этому BMC. Возвращает уверенность и инфо.
  async probe(cfg, sdk) -> { matched, confidence, info },

  // 2) Вход: КАК вводить креды (схема платформы). Креды даёт ядро.
  async login(cfg, sdk) -> sessionCfg,

  // 3) Консоль видео+HID (обязателен, если capabilities.kvm).
  createConsole(sessionCfg, events, sdk) -> ConsoleClient,

  // 4) Виртуальный носитель (опционален).
  createMedia(sessionCfg, { isoPath }, sdk) -> MediaRedirector,
};
```

Контракты ядра (канон, общий для всех):
- `ConsoleClient`: `start()`, `close()`, `keyEvent(hid, down)`,
  `mouseAbs(x,y)`, `mouseButtons(x,y,mask,wheel)`, `fb() -> {width,height,pix}`;
  события `onStatus/onFrame/onError/onExit`.
- `MediaRedirector`: `start()`, `close()`, `stats() -> {bytes,bps,active}`.
- **Канон пикселей: `fb.pix = 0x00RRGGBB`** (R — старший байт). Приведение
  каналов к канону — обязанность модуля. Общий RFB-мост (vnc.js) и PNG
  работают только с каноном и НЕ компенсируют чужой формат.
- `sdk`: логгер, пути ISO, доступ к сессиям/событиям, версия контрактов.
  Модуль работает только через `sdk`.

## Границы «ядро ↔ модуль»

| Ядро (shared)                             | Модуль платформы                          |
|-------------------------------------------|-------------------------------------------|
| Контракты, реестр, загрузчик (`sdk/`)      | Пробы, порты, доступ                      |
| RFB-мост `vnc.js`, PNG `png.js` (канон)    | Декодер видео/формат пикселей             |
| Сессии, WS, UI, авторизация/хранение creds | Схема входа (digest/форма/Basic/…)        |
| Хранилище ISO, mount-API                   | Транспорт и протокол виртуального носителя|
| IPMI-транспорт (RMCP+ примитивы)           | Что именно платформа отдаёт по IPMI       |
| БД, события, дерево серверов               | Quirks/обходы конкретной платформы        |

## Чеклист добавления модуля (для человека или ИИ)

1. Создать `server/platforms/<id>/`.
2. Написать `manifest.js`: `supported` (модели+прошивки), `access`
   (порты/способы), `capabilities`, `probes`, `priority`, `sdk`.
3. Реализовать в `index.js` только нужные контракты (не обязательно все:
   например, без виртуальных носителей — просто не объявлять cap).
4. Пробы — в `probe.js`, имена перечислены в `manifest.probes`.
5. `README.md`: что проверено, на какой прошивке, грабли.
6. `test.js` (по желанию) — самотест; `npm test` подхватит.
7. Никаких правок ядра. Запись в `wiki/knowledge/platforms/<id>.md` + `index.md`.
