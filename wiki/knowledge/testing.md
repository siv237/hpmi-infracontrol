# Тестирование фронтенда — стек и best practices

Разрез монолита `web/index.html` (2026-09-08) опирается на **стандартный тест-стек
Node.js** и e2e-проверку браузерного приложения. Проект — SPA «без сборки»
(классические скрипты по порядку), поэтому тестовый стек выбран под это.

## Стек

- **Unit / интеграция — `node:test`** (встроенный тест-раннер Node >=18, без
  зависимостей). Запуск: `npm test` → `node --test test/`.
  Имена файлов `test/*.test.js`.
- **E2E-смок — `puppeteer-core`** (исполняемый браузер **не** бандлится — нужен
  системный Chrome/Chromium). Запуск только по явной команде и при поднятом
  сервере: `CHROME=/usr/bin/google-chrome npm run test:e2e`. Без сервера на
  `E2E_BASE_URL` (по умолч. `http://127.0.0.1:1845`) и без браузера — тест
  **аккуратно пропускается** (не поднимает сервер сам, не падает в CI).

## Правила ведения (best practices)

1. `npm test` должен быть зелёным всегда; `./start.sh` не трогает тесты.
2. E2e-**смок** проверяет только жизненный цикл загрузки: GET `/` 200, каждый
   css/js-модуль разреза отдаёт 200, появляется экран входа, нет inline
   `<style>`/`<script>`, нет незакрытых JS-ошибок. Детальные сценарии — не сюда.
3. **`page error` против `console`:** при просроченном токене `/api/me` даёт
   401 — это штатный флоу (api() показывает вход), сетевой шум
   «Failed to load resource … 401» не считаем ошибкой. Критичны только
   незакрытые исключения (`pageerror`) и явные JS-ошибки консоли.
4. Тесты **структуры моно-файлов** (текущий `test/web-split.test.js`) —
   регрессионная защита разреза:
   - индекс не содержит inline `<style>`/`<script>` без `src`;
   - каждый модуль из index существует, сирот нет;
   - синтаксис каждого `.js` и **всей связки модулей в порядке подключения**;
   - набор top-level `function`-имён ровно равен ожидаемому (ничего не
     потеряно/не продублировано после вставки/переноса кода);
   - **нет дублей top-level имён между классическими скриптами** (общий global
     scope — переопределение `let/const/function` сломает приложение);
   - каждый `$("id")`, на который ссылается JS, существует в HTML;
   - сервер имеет роут `/css|js` (отдача модулей).
5. **При изменении состава модулей** (добавили/переименовали файл, добавили
   функцию) правь в тесте списки `CSS_FILES`/`JS_FILES`/`EXPECTED_FUNCTIONS` и
   порядок подключения в `index.html` синхронно — иначе тест укажет расхождение.
6. Тесты расширяются по мере роста: держи пирамиду (много unit, один e2e-смок),
   не дублируй проверку одного и того же в e2e и unit.

## Как проверить разрез вручную (для владельца)

1. Unit: `npm test`.
2. Поднять сервер: `./start.sh` (порт 1845), обновить страницу `Ctrl+Shift+R`.
3. E2E: `CHROME=$(which google-chrome || which chromium) npm run test:e2e`.
