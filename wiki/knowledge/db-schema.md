# Схема БД собранных IPMI-данных (фаза 2)

Единая SQLite-база `data/db/ipmi.sqlite` (better-sqlite3, WAL) — весь сбор
с IPMI. Инвариант: **`rm -rf data/db/` стирает весь сбор и только его**;
настройки (servers.json, интервалы, состав опроса) вне БД — после удаления
система сразу продолжает опрос тех же серверов.

## Таблицы

| Таблица | Что хранит | Рост |
|---|---|---|
| `sensors` | справочник сенсоров (server_id+name, kind temp/fan, units) | медленный |
| `sensor_state` | текущее значение сенсора (upsert) | нет |
| `sensor_history` | история ТОЛЬКО изменений значений | медленный |
| `server_state` | состояние сервера: up, last_ok_ts, power, faults, FRU, poll_error | нет |
| `polls` | журнал КАЖДОГО опроса (ts, ok, duration_ms, error) | линейный |
| `avail_changes` | переходы up/down — только смена | редкие |
| `sel_events` | SEL-события, дедуп UNIQUE(server_id,sel_id,sel_ts,sensor,detail), INSERT OR IGNORE | редкие |
| `sel_last` | последний снимок SEL-журнала (JSON) | нет |
| `last_known` | last-known инвентарь (снимок /api/info) | нет |
| `config_changes` | изменения ключевых полей | редкие |
| `versions` | история версий оборудования | редкие |
| `events` | единый журнал (SEL-критика + переходы + операционные) | линейный |

## Принципы

1. **Транзакция на опрос** (`recordPoll`/`recordPollFailure`): полусобранных
   опросов не бывает — либо весь, либо ничего. Что успело записаться до
   отказа сервера/сборщика — доступно (`pollCache` отдаёт последний успешный
   снимок + `poll_error`).
2. **Дедуп SEL в самой БД**: UNIQUE-индекс + INSERT OR IGNORE — повторы от
   60-секундных опросов и рестартов не пишутся (прежний дедуп в памяти
   плодил тысячи дублей и терялся при рестарте).
3. **История — только изменения**: sensor_history растёт лишь при отличии
   значения от предыдущего. Чтение рядов — forward-fill по точкам
   изменений; доступность — по длительностям состояний (avail_changes),
   а не по числу точек.
4. **Упавший сервер не затирает данные**: recordPollFailure ставит up=0 +
   poll_error, но не трогает last_ok_ts/power/faults/FRU — в БД видно,
   когда сервер последний раз отвечал.
5. **Ретеншн** (`prune(30)`): чистит историю/журналы > 30 дней, состояние
   не трогает (оно актуальное, не историческое).

## Вне БД (не сбор)

`servers.json` (конфиги+креды AES), `users.json` (scrypt), `ui.json`,
`key.bin`, `data/iso/` + `.meta.json`, `data/storage.json` (только mounts —
операционное состояние ISO), `data/m2/`.

## Миграция (разовая, при старте)

`migrateLegacy()` переносит `data/metrics.sqlite` (ряды сенсоров/ping/
response_ms → polls, avail_changes, sensor_history; сжатие дублей точек) и
`data/storage.json` (lastKnown/changes/versions/events) в новую схему;
`freezeLegacy()` переименовывает старые файлы в `*.migrated` (архив, не
удаляются). На копии прод-данных: 32472 точки сенсоров, 3128 пингов,
121 событие, 97 версий — переносится за < 1 c.

## Совместимость API

Форматы ответов `/api/ipmi/*`, `/api/overview`, `/api/last-known`,
`/api/changes`, `/api/events`, `/api/versions` не изменились: series()
понимает старые имена метрик ('temp:X', 'fan:X', 'response_ms', 'ping'),
lastValues() отдаёт ключи с префиксами, pollCache() — форму sensorCache.
Фронт работает без изменений.

## Проверено (песочница, копия данных)

- миграция 35 824 записей < 1 c; инвариант data/db/ соблюдён;
- recordPoll: 0 записей при отсутствии изменений, 1 при изменении CPU1;
- SEL-дубликат не пишется (счётчик = 1 при двух одинаковых опросах);
- отказ опроса: состояние живо, avail корректно (up 180c из 200c → 90.9%);
- первый успешный опрос фиксирует переход up (первое наблюдение);
- доступность до первого наблюдения не считается (нет ложных 100%).
